## How I work

- **Design for the failure path first.** I write down what happens when a queue, payment or third-party call fails before I write the happy path.
- **Keep the hot path fast.** Latency-critical endpoints (like a redirect) should not wait on slow writes.
- **Ship with the pipeline.** Docker, GitHub Actions and cloud deployment are part of the feature, not an afterthought.
- **Explain the "why".** Commits, PRs and READMEs record decisions, not just changes.
